# Рядом — твой город на ладони

Мобильный frontend для Енисейска (Красноярский край): афиша, места и локальные услуги. React 19, TypeScript, Vite и обычный CSS. Настоящего backend, платежей и регистрации нет. Места — реальные: первая подборка из 10 мест основана только на данных, предоставленных пользователем 6 октября 2026 года, без самостоятельной проверки и дополнений из интернета. Афиша и услуги содержат вымышленные демонстрационные данные.

## Запуск

Нужен Node.js 20.19+ или 22.13+ (проверено на Node.js 24) и npm.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). В обычном браузере работает гостевой профиль. Если Telegram SDK не загрузился или недоступен, приложение остаётся работоспособным.

```sh
npm run lint
npm run build
npm run preview
```

Сборка создаёт `dist/`. `preview` проверяет production-сборку локально, обычно на порту 4173. Для повторяемой установки используйте `npm ci` с сохранённым `package-lock.json`. Если домашний каталог недоступен для записи, добавьте `--cache /workspace/.npm-cache` к команде установки.

## Возможности

- Выбор города в bottom sheet: пока доступен только Енисейск. Город сохраняется в `localStorage` (`ryadom.city`); каталоги, поиск, подборки, детали и избранное показывают только записи выбранного города. Недоступное или повреждённое сохранённое значение заменяется на Енисейск.
- Главная с приветствием, глобальным поиском, быстрыми разделами и подборками.
- Афиша: категории, фильтры «Сегодня» / «Завтра», время, цена и подробности.
- Места: кафе, музеи, достопримечательности и парки; только переданные адреса, телефоны, описания и часы работы. Рейтинги и неизвестные цены скрыты. Для графика показано напоминание уточнять его перед посещением.
- Услуги: категории, исполнитель, примерная цена, рейтинг и подробности.
- Избранное всех типов, сохранённое в `localStorage`; фильтрация по типу.
- Профиль Telegram с доступными именем, username и аватаром; гостевой режим.
- Светлая, тёмная и автоматическая тема. Авто использует Telegram, а в браузере — системную тему.
- Нижняя навигация, SVG-иконки, локальные иллюстрации, безопасные отступы экрана, поддержка уменьшения анимации и клавиатуры.
- Ссылки на экраны через hash (`/#/events`, `/#/places/place-kytmanov-museum`), история браузера, Telegram BackButton и Escape на детальном экране.

Демонстрационные даты вычисляются относительно дня просмотра, чтобы блок «Сегодня» всегда содержал примеры. Избранное и тема привязаны к браузеру / WebView и не синхронизируются между устройствами. При запрете `localStorage` избранное работает в памяти и появляется пояснение.

## Структура

```text
src/
  components/  Карточки, поиск, навигация, иконки, пустые состояния
  pages/       Главная, каталог, детали, избранное, профиль
  data/        Реальные места, демо-афиша и услуги, категории и города
  hooks/       Telegram, избранное, hash-навигация
  utils/       Поиск, даты, безопасное хранение
  types/       Модели каталога и Telegram WebApp
  assets/      Локальные SVG-иллюстрации
  App.tsx      Компоновка экранов
  styles.css   Адаптивный интерфейс и темы
```

## Web / PC и Telegram

В обычном браузере от 900 px используется отдельная desktop-компоновка: верхняя sticky-шапка, контейнер до 1280 px, hero, быстрые разделы, сетки по 3 карточки, footer и страницы мест в две колонки. Нижняя мобильная навигация в этом режиме не рендерится. Поиск и избранное используют те же данные и localStorage.

На мобильном и планшете сохранена компактная версия. Внутри Telegram она используется на любой ширине; desktop-компоненты не показываются. Определение Telegram использует существующий `useTelegram`, включая отличие настоящего WebApp от пустого SDK в браузере. Цвета и SVG остаются прежними. В браузере профиль гостевой, без фиктивного Telegram-имени. Web-кнопки перехода в Telegram удалены; сам Mini App сохранён.

## Источник данных мест

`src/data/places.ts` содержит ровно 10 переданных пользователем мест Енисейска. `real: true`, `verifiedAt: "2026-10-06"` и `sourceType: "user_provided"` обозначают происхождение и дату переданного списка, а не независимую проверку. Неизвестные поля отсутствуют. Категории с уточнениями («Музеи / История», «Парки / Прогулки») объединяются соответствующими основными фильтрами.

Используются только существующие локальные SVG-иллюстрации; это не фотографии мест. Новые идентификаторы реальных мест не переиспользуют ID удалённых демо-мест, поэтому прежние сохранения не превращаются в избранное других организаций.

## Telegram и безопасность

Официальный SDK загружается с `https://telegram.org/js/telegram-web-app.js`. В приложении вызываются `ready()` и `expand()`, читаются `initDataUnsafe.user` и `colorScheme`. Фирменная палитра едина для браузера и Telegram. Изменения темы обрабатываются через `themeChanged`. Настройка темы пользователем имеет приоритет над автоматической темой.

`initDataUnsafe` используется исключительно для отображения. Это **не подтверждённая авторизация**. Перед защищёнными операциями будущий backend должен проверять подпись и срок действия `initData` согласно документации Telegram. Данные профиля сейчас не отправляются на сервер. SDK и аватар Telegram могут выполнять сетевые запросы.

Для гостевого режима переменные окружения не нужны. Для будущего Supabase-подключения подготовлен `.env.example` с пустыми публичными параметрами. Никогда не помещайте Bot Token в `VITE_*`: такие значения попадут в клиентскую сборку. Необходимые реальные контакты, запись, оплата и отправка заявок в этом MVP отсутствуют.

## Публикация и подключение

1. Выполните `npm ci`, `npm run lint` и `npm run build`.
2. Разместите содержимое `dist/` на статическом хостинге с HTTPS (например, Cloudflare Pages, Netlify или Vercel). Команда сборки — `npm run build`, каталог публикации — `dist`. Hash-навигация не требует серверных rewrite-правил. Проект настроен для корня домена; для вложенного пути задайте `base` в Vite.
3. Создайте бота через официальный `@BotFather`, если его ещё нет. Токен храните только на сервере при будущем подключении backend; текущему frontend он не нужен.
4. В `@BotFather` откройте `/mybots` → ваш бот → Bot Settings → Configure Mini App / Menu Button и задайте HTTPS-адрес опубликованного приложения. Названия пунктов могут меняться. `/setmenubutton` позволяет настроить кнопку меню.
5. Проверьте открытие в Telegram на iOS, Android и Desktop: профиль, темы, BackButton, прокрутку и safe area. Определите главный Mini App для кнопки запуска в профиле бота, если она нужна.

Публикация, настройка BotFather и проверка на реальных устройствах выполняются отдельно. Подключение реального каталога, проверка `initData` на сервере и синхронизация избранного — следующие этапы.

## Брендинг

Название вкладки и Open Graph: «Рядом — твой город на ладони». Цвета светлой и тёмной тем заданы в `src/styles.css`: тёплый молочный фон, primary для CTA и точечные голубые, коралловые и жёлтые акценты разделов. `BrandMark` используется в шапке, профиле и футере; пути значков вынесены в `src/utils/brand.ts`.

В `public/brand/` сохранены оригинальные PNG пользователя: `star-blue.png` (брендовый знак и favicon) и `vk.png` (ссылка на VK в футере). Прозрачность сохранена; временные SVG-заглушки удалены.

## Яндекс Метрика

Счётчик `113480026` подключён официальным `tag.js` без дополнительных библиотек. `src/main.tsx` запускает `src/analytics/yandexMetrika.ts` один раз вне React. Автоматический просмотр отключён через `defer: true`: первый просмотр и изменения hash/истории отправляются вручную; одинаковый текущий URL не отправляется повторно, предыдущий URL передаётся как `referer`. OAuth-параметры и служебные Telegram-фрагменты исключаются из URL просмотров.

JavaScript-счётчик разрешён только в production-сборке на `https://ryadomcity.ru`. Localhost, IP-адреса и Netlify preview не загружают его. `noscript`-пиксель из `index.html` сохраняется только при сборке с `CONTEXT=production` (Netlify задаёт это автоматически); в dev, локальной сборке и deploy preview Vite удаляет его. При публикации на другом хостинге задайте `CONTEXT=production` для production-сборки. Блокировка Метрики не мешает работе приложения.

## Аккаунты и Supabase

`src/lib/supabase.ts` создаёт один официальный Supabase client. Для браузера используются `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_…`) из `.env.local` или настроек сборки Netlify. Реальные значения не входят в Git. `SUPABASE_SECRET_KEY`, service_role, secret key, пароль базы, OAuth secrets и Bot Token запрещены во frontend. Отсутствующая или неподходящая конфигурация оставляет приложение в гостевом режиме; в dev console появляется предупреждение без значений ключей. После изменения env нужна новая сборка/перезапуск Vite.

`AuthProvider` / `useAuth` восстанавливают настоящую Supabase Auth session через getSession и подписываются на onAuthStateChange. Профиль загружается по auth.user.id из profiles, identities только читаются из user_identities. Пустой профиль не превращает пользователя в гостя и не ломает страницу. `updateProfile` обновляет только display_name, avatar_url и city текущего пользователя. «Выйти» вызывает Supabase signOut, очищает состояние аккаунта и сохраняет локальное гостевое избранное.

Гостевое избранное использует прежний localStorage. При первом входе аккаунт получает объединённый список: отсутствующие локальные ID добавляются в user_favorites без перезаписи сервера. Кеш и отметка импорта хранятся отдельно по UUID аккаунта. Последующие добавления/удаления выполняются через Supabase с оптимистичным UI и откатом при ошибке. При недоступной сети отображается сообщение с повтором; RLS остаётся основным механизмом ограничения доступа.

`#/login` сохранён. Яндекс ID запускает Supabase OAuth через `custom:yandex`; остальные VK ID, Telegram и Google отключены с пометкой «Подключение настраивается», MAX — «скоро». Автоматический Telegram-вход не подключён. initDataUnsafe используется только для отображения; будущий вход через Telegram требует серверной проверки initData. Без настоящей Supabase session интерфейс остаётся гостевым.

Схема таблиц и RLS подготовлены в `supabase/schema.sql` и по сообщению пользователя уже настроены в Supabase. Приложение не применяет SQL автоматически. Подробности lifecycle, кеша, ограничений и следующих шагов: [docs/accounts.md](docs/accounts.md).
