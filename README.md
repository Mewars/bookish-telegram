# Рядом — твой город на ладони

Адаптивный сайт для Енисейска (Красноярский край): афиша, места и локальные услуги. React 19, TypeScript, Vite и обычный CSS. Авторизация и профили работают через Supabase Auth; платежей нет. Места — реальные: первая подборка из 10 мест основана только на данных, предоставленных пользователем 6 октября 2026 года, без самостоятельной проверки и дополнений из интернета. Афиша и услуги содержат вымышленные демонстрационные данные.

## Запуск

Нужен Node.js 20.19+ или 22.13+ (проверено на Node.js 24) и npm.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). Без входа доступен гостевой режим.

```sh
npm run lint
npm run build
npm run preview
```

Сборка создаёт `dist/`. `preview` проверяет production-сборку локально, обычно на порту 4173. Для повторяемой установки используйте `npm ci` с сохранённым `package-lock.json`. Если домашний каталог недоступен для записи, добавьте `--cache /workspace/.npm-cache` к команде установки.

## Возможности

- Выбор города в bottom sheet: пока доступен только Енисейск. Город сохраняется в `localStorage` (`ryadom.city`); каталоги, поиск, подборки, детали и избранное показывают только записи выбранного города. Недоступное или повреждённое сохранённое значение заменяется на Енисейск.
- Главная с приветствием, глобальным поиском, быстрыми разделами и подборками.
- Афиша: категории, фильтры «Сегодня» / «Завтра», время, цена и подробности.
- Места: кафе, музеи, достопримечательности и парки; только переданные адреса, телефоны, описания и часы работы. Рейтинги и неизвестные цены скрыты. Для графика показано напоминание уточнять его перед посещением.
- Услуги: категории, исполнитель, примерная цена, рейтинг и подробности.
- Избранное всех типов, сохранённое в `localStorage`; фильтрация по типу.
- Профиль аккаунта Supabase, вход по email и Яндекс ID; гостевой режим.
- Светлая, тёмная и автоматическая тема. Авто использует системную тему устройства.
- Нижняя навигация, SVG-иконки, локальные иллюстрации, безопасные отступы экрана, поддержка уменьшения анимации и клавиатуры.
- Ссылки на экраны через hash (`/#/events`, `/#/places/place-kytmanov-museum`), история браузера, Escape на детальном экране.

Демонстрационные даты вычисляются относительно дня просмотра, чтобы блок «Сегодня» всегда содержал примеры. Гостевое избранное и тема привязаны к браузеру; избранное аккаунта синхронизируется через Supabase. При запрете `localStorage` избранное работает в памяти и появляется пояснение.

## Структура

```text
src/
  components/  Карточки, поиск, навигация, иконки, пустые состояния
  pages/       Главная, каталог, детали, избранное, профиль
  data/        Реальные места, демо-афиша и услуги, категории и города
  hooks/       Тема устройства, избранное, hash-навигация
  utils/       Поиск, даты, безопасное хранение
  types/       Модели каталога и аккаунтов
  assets/      Локальные SVG-иллюстрации
  App.tsx      Компоновка экранов
  styles.css   Адаптивный интерфейс и темы
```

## Компьютеры и смартфоны

В обычном браузере от 900 px используется отдельная desktop-компоновка: верхняя sticky-шапка, контейнер до 1280 px, hero, быстрые разделы, сетки по 3 карточки, footer и страницы мест в две колонки. Нижняя мобильная навигация в этом режиме не рендерится. Поиск и избранное используют те же данные и localStorage.

На экранах меньше 900 px используется компактная версия с адаптивной шапкой и нижней навигацией. Компоновка определяется только шириной окна. Цвета и SVG сохранены. Профиль доступен и на телефоне, и на компьютере; без Supabase session пользователь остаётся гостем.

## Источник данных мест

`src/data/places.ts` содержит ровно 10 переданных пользователем мест Енисейска. `real: true`, `verifiedAt: "2026-10-06"` и `sourceType: "user_provided"` обозначают происхождение и дату переданного списка, а не независимую проверку. Неизвестные поля отсутствуют. Категории с уточнениями («Музеи / История», «Парки / Прогулки») объединяются соответствующими основными фильтрами.

Используются только существующие локальные SVG-иллюстрации; это не фотографии мест. Новые идентификаторы реальных мест не переиспользуют ID удалённых демо-мест, поэтому прежние сохранения не превращаются в избранное других организаций.

## Публикация и подключение

1. Выполните `npm ci`, `npm run lint` и `npm run build`.
2. Разместите содержимое `dist/` на статическом хостинге с HTTPS (например, Cloudflare Pages, Netlify или Vercel). Команда сборки — `npm run build`, каталог публикации — `dist`. Hash-навигация не требует серверных rewrite-правил. Проект настроен для корня домена; для вложенного пути задайте `base` в Vite.
3. Проверьте сайт в браузерах компьютера и смартфона: темы, профиль, нижнюю навигацию, прокрутку и safe area.
4. Для аккаунтов задайте публичную конфигурацию Supabase из `.env.example`. OAuth-настройки описаны в [docs/accounts.md](docs/accounts.md), подготовка VK ID — в [docs/vk-id.md](docs/vk-id.md).

## Карты мест: OpenStreetMap + ссылки открытия карт

В карточке реального места с подтверждёнными координатами посетитель нажимает **«Показать карту»** и загружает интерактивный OpenStreetMap (встраивание `https://www.openstreetmap.org/export/embed.html`). При отсутствии координат карта не угадывает адрес. Сохраняется внешняя ссылка `Открыть в Яндекс Картах` из `src/maps/placeMapLinks.ts`; она ведёт на обычную публичную страницу Яндекса и не требуют Яндекс Maps JavaScript API или платного ключа. Координаты формируются только из нашей карточки, геокодинга/копирования данных Яндекса нет.

Загрузка встроенной карты происходит **только после нажатия**, а не при каждом просмотре карточки. Есть видимое указание © участники OpenStreetMap и ссылка на лицензию, а также запасная ссылка для открытия карты на OSM, если встраивание заблокировано у посетителя.

Для небольшого тестового запуска используется официальный публичный сервис OpenStreetMap, доступность без VPN **ещё не проверена**. В будущей коммерческой версии и франшизе необходимо выбрать провайдера тайлов с коммерческими условиями/SLA либо развернуть собственную карту на OSM-данных: публичные серверы OSM не являются бесплатной инфраструктурой для высокой нагрузки. См. [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) и [лицензию ODbL](https://www.openstreetmap.org/copyright). Тестирование провайдера и замена iframe на брендированный Leaflet/MapLibre — отдельный этап.

Переменная `VITE_YANDEX_MAPS_API_KEY` **не используется и в Timeweb для текущей карты не нужна**. Не создавать или оплачивать Яндекс Maps API ради встроенной карты. Кнопки построения маршрута не отображаются; ссылки открытия карт OSM/Яндекса сохранены, без SDK. Проверка: `npm run test:maps` и `npm run test:osm`.

## Яндекс Метрика

Счётчик `113480026` подключён официальным `tag.js` без дополнительных библиотек. `src/main.tsx` запускает `src/analytics/yandexMetrika.ts` один раз вне React. Автоматический просмотр отключён через `defer: true`: первый просмотр и изменения hash/истории отправляются вручную; одинаковый текущий URL не отправляется повторно, предыдущий URL передаётся как `referer`. OAuth-параметры исключаются из URL просмотров.

JavaScript-счётчик разрешён только в production-сборке на `https://ryadomcity.ru`. Localhost, IP-адреса и Netlify preview не загружают его. `noscript`-пиксель из `index.html` сохраняется только при сборке с `CONTEXT=production` (Netlify задаёт это автоматически); в dev, локальной сборке и deploy preview Vite удаляет его. При публикации на другом хостинге задайте `CONTEXT=production` для production-сборки. Блокировка Метрики не мешает работе приложения.

## Аккаунты и Supabase

`src/lib/supabase.ts` создаёт один официальный Supabase client. Для браузера используются `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_…`) из `.env.local` или настроек сборки Netlify. Реальные значения не входят в Git. `SUPABASE_SECRET_KEY`, service_role, secret key, пароль базы, OAuth secrets запрещены во frontend. Отсутствующая или неподходящая конфигурация оставляет приложение в гостевом режиме; в dev console появляется предупреждение без значений ключей. После изменения env нужна новая сборка/перезапуск Vite.

`AuthProvider` / `useAuth` восстанавливают настоящую Supabase Auth session через getSession и подписываются на onAuthStateChange. Профиль загружается по auth.user.id из profiles, identities только читаются из user_identities. Пустой профиль не превращает пользователя в гостя и не ломает страницу. `updateProfile` обновляет только display_name, avatar_url и city текущего пользователя. «Выйти» вызывает Supabase signOut, очищает состояние аккаунта и сохраняет локальное гостевое избранное.

Гостевое избранное использует прежний localStorage. При первом входе аккаунт получает объединённый список: отсутствующие локальные ID добавляются в user_favorites без перезаписи сервера. Кеш и отметка импорта хранятся отдельно по UUID аккаунта. Последующие добавления/удаления выполняются через Supabase с оптимистичным UI и откатом при ошибке. При недоступной сети отображается сообщение с повтором; RLS остаётся основным механизмом ограничения доступа.

`#/login` сохраняет вход, регистрацию и восстановление по email и Яндекс ID (`custom:yandex`). Подготовлен вызов `custom:vk`: кнопка VK ID включается только после настройки и проверки серверного провайдера через `VITE_VK_ID_ENABLED=true`. По умолчанию VK ID отключён. См. [docs/vk-id.md](docs/vk-id.md). Без настоящей Supabase session интерфейс остаётся гостевым.

Схема таблиц и RLS подготовлены в `supabase/schema.sql` и по сообщению пользователя уже настроены в Supabase. Приложение не применяет SQL автоматически. Подробности lifecycle, кеша, ограничений и следующих шагов: [docs/accounts.md](docs/accounts.md).
