# Подключение «Рядом» к Яндекс Вебмастеру и Google Search Console

Основной адрес: **https://ryadomcity.ru/**, без www.
Sitemap: **https://ryadomcity.ru/sitemap.xml**.

Это инструкция для владельца. Никакие DNS/NS записи, verification tokens, права владения, настройки SSL или счётчик Метрики этим PR не изменяются. Не публикуйте вымышленные коды: значения выдаёт выбранный сервис для вашего аккаунта.

## 1. Проверить сайт до подключения

После согласованного выпуска SEO-сборки и загрузки содержимого ZIP в корень сайта:

1. Откройте основной HTTPS URL, убедитесь в действующем сертификате, загрузке главной и отсутствии редиректов на технический домен. Если SSL ещё не работает, сначала решить это с владельцем хостинга; считать HTTPS-проверку пройденной нельзя.
2. Откройте `/robots.txt`: текстовый файл с `Sitemap: https://ryadomcity.ru/sitemap.xml`, а не React HTML/ошибка/экран входа.
3. Откройте `/sitemap.xml`: XML с корневым `<urlset>` и единственным loc `https://ryadomcity.ru/`. Без hash, login, profile, favorites и import.
4. Откройте исходный HTML главной (именно View Source): уникальные title/description, один canonical основного URL, OG/Twitter, WebSite JSON-LD. Обычный DOM Inspector показывает уже результат JavaScript и не заменяет эту проверку.
5. Откройте `/brand/yeniseysk-hero-final.jpg` и `/brand/pin-yellow.svg`: доступны без авторизации, CAPTCHA и блокировки ботов, с правильным типом файла. Preview платформ может кешироваться; после обновления используйте их инструменты повторного сканирования, если доступны.
6. Не закрывайте `/assets/`, `/brand/`, JS/CSS и изображения в robots: они нужны для rendering. HTTP headers `X-Robots-Tag`/серверные noindex должны отдельно проверяться на реальном хостинге.

Проверять HTML/robots публично безопасно; реальную авторизацию проверять только на действующем HTTPS, не на HTTP техническом адресе.

## 2. Яндекс Вебмастер

1. Войдите в свой аккаунт на https://webmaster.yandex.ru/ и выберите добавление сайта.
2. Введите **https://ryadomcity.ru/**. HTTP и www варианты не используйте как основной сайт; если они существуют, отдельно проверить корректные canonical/redirects после согласования владельцем.
3. Подтвердите права выбранным способом из текущего интерфейса:
   - **DNS TXT**, если этот способ предложен: сервис выдаёт точное имя/значение. Владелец добавляет TXT в зоне **ryadomcity.ru у текущего DNS-провайдера**, затем ждёт распространения и нажимает проверку. Не меняйте NS, A/AAAA/CNAME/MX, hosting records и чужие TXT. Несколько verification TXT могут сосуществовать; не заменяйте записи других сервисов.
   - **HTML-файл**: скачайте файл, выданный Вебмастером, и разместите его с неизменным именем/содержимым в корне public_html. Убедитесь, что URL отдаёт именно этот файл, а не SPA HTML. При желании хранить файл в репозитории — добавить реальный файл в `public/` отдельной задачей, чтобы последующий ZIP его не потерял.
   - **Meta-тег**: вставьте точный код, выданный сервисом, в head исходного `index.html` отдельной согласованной правкой. Не добавляйте через React: проверяющий сервис может не выполнять JS.
   - Другие предложенные сервисом способы используйте только при наличии соответствующих прав; существующий счётчик Метрики менять или пересоздавать не нужно.
4. После подтверждения в разделе индексирования / файлов Sitemap добавьте **https://ryadomcity.ru/sitemap.xml**. Названия разделов интерфейса могут меняться.
5. Проверьте статус обработки, дату сканирования, ошибки загрузки и URL. Пока sitemap должен содержать одну страницу; hash-разделы не являются пропущенными отдельными HTML.
6. Используйте проверку URL/статуса страницы и инструмент проверки ответа сервера/доступности для `https://ryadomcity.ru/`. При доступности инструмента анализа JavaScript/rendering проверьте, что робот видит H1 «Енисейск», название музея и содержимое разделов, а не только root/noscript. Одного HTTP 200 недостаточно.
7. В индексировании и диагностике смотрите исключённые страницы, ошибки сервера/сканирования, robots/noindex, дубли и выбранный основной адрес. Переобход запрашивайте для реальной главной после исправлений, не для множества hash URLs.
8. В поисковых запросах/статистике смотрите показы, клики, CTR, позиции, устройства и периоды. Свежий сайт может ещё не иметь данных; sitemap и подтверждение прав не гарантируют включение в индекс или позиции.

## 3. Google Search Console

1. Войдите на https://search.google.com/search-console/ под аккаунтом владельца.
2. Выберите один из вариантов:
   - **Domain property**: введите `ryadomcity.ru` без протокола и пути. Подтверждение обычно DNS TXT, включает протоколы и поддомены. Скопируйте реальное значение, добавьте TXT в текущую DNS-зону вручную через владельца; NS и рабочие записи не менять.
   - **URL-prefix property**: введите `https://ryadomcity.ru/`. Используйте поддерживаемый способом интерфейса HTML-файл/meta-тег или другие доступные владельцу методы. Для файла/meta действуют те же правила исходного HTML и сохранения файла при ZIP-обновлении.
3. Нажмите проверку после публикации подтверждения/распространения DNS. Не удаляйте verification record/tag/file после успеха: права могут перепроверяться. Не публикуйте секретные аккаунтные данные; использовать нужно только verification value, предназначенное сервисом для размещения.
4. Откройте **Sitemaps** и отправьте `https://ryadomcity.ru/sitemap.xml` (для URL-prefix интерфейс может запрашивать относительное `sitemap.xml`). Убедитесь в статусе Success и ожидаемом числе URL.
5. Через **URL Inspection** проверьте `https://ryadomcity.ru/`: доступность для crawling, robots/noindex, пользовательский и выбранный Google canonical, текущий статус индексации.
6. Запустите **Test live URL**, затем просмотр tested page: HTML, screenshot, JS console/resource errors. В rendered HTML ищите H1 «Енисейск» и реальное название из каталога (например музей Кытманова). Если присутствует только noscript/пустой root, проверить доступность bundle и внешних ресурсов; запросить исправление, а не объявлять полноценную индексацию SPA выполненной.
7. После успешной диагностики можно запросить индексирование главной. Live test подтверждает возможность загрузки сейчас, но не заменяет статус реально проиндексированной страницы.
8. В **Page indexing** отслеживайте excluded/duplicate/crawled-not-indexed/discovered-not-indexed/soft-404 и server errors. В **Performance / Search results** смотрите запросы, страницы, показы, клики, CTR, позиции, страны и устройства. Данные появляются с задержкой; поиск `site:ryadomcity.ru` — лишь дополнительная проверка, не полный отчёт об индексе.

## 4. Проверка React и социальных ссылок

- Raw HTML должен содержать метаданные без JavaScript; rendered HTML — публичное содержимое приложения. Проверить оба слоя в инструменте поисковика.
- Ссылка `/#/places/...` открывает нужную карточку пользователю, но сервер выдаёт общий index.html. JS title/description не превращают её в отдельный индексируемый документ, а соцсети обычно используют общие OG-теги главной.
- WebSite JSON-LD не даёт гарантии rich results. Не публиковать разметку Event/LocalBusiness для демонстрационных записей.
- Для устойчивой индексации карточек нужен отдельно согласованный этап статической генерации/пререндеринга реальных страниц. План — [seo-audit.md](seo-audit.md).

## 5. Регулярная проверка

После каждого существенного выпуска: HTTPS/основной URL → robots/sitemap → raw HTML/OG → live rendering → ошибки индексирования. Еженедельно сравнивать показы/клики/запросы и мобильные устройства по сопоставимым периодам. Не считать отсутствие статистики сразу после добавления сайта технической ошибкой и не менять DNS/серверную структуру ради ускорения индексации без отдельного согласования.
