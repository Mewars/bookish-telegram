# Админка «Рядом» — безопасная подготовка

Этап 1: защищённая CMS мест и организаций в разделе «Услуги» (добавление, редактирование, загрузка фотографии, черновик / публикация / архив).
**По умолчанию выключена** и не меняет действующие данные / Supabase / аутентификацию.

## Сначала проверка, потом запуск

1. Убедиться, что есть рабочая резервная копия базы и известен пользователь-владелец.
2. В отдельном тестовом Supabase проверить `docs/sql/organizations.sql`, затем `docs/sql/organizations-seed.sql` (8 существующих мест), затем `docs/sql/organizations-seed-reviewed-2026-10.sql` (17 проверенных по источникам новых организаций). Если таблица уже есть, не запускайте базовую схему повторно: проверьте структуру.
3. Проверить новый `docs/sql/city-admin-mvp.sql` в тестовом проекте, затем вручную применить в рабочем Supabase. Миграция **не выполняется автоматически**.
4. В Supabase Authentication → Users скопировать **реальный UUID собственной учётной записи** (не присылать его в чат). В SQL Editor вручную выполнить последнюю закомментированную команду из файла `city-admin-mvp.sql` со своим UUID и `'*'` (owner).
5. Убедиться, что остальные пользователи не имеют строк в `city_admin_access` (и не могут сами добавлять их).
6. После успешных тестов в GitHub Actions сборки добавить **Repository Variable** `VITE_ADMIN_PANEL_ENABLED=true` и убедиться, что она доступна Production Build; для автоматической публикации на Спринтхост она должна передаваться в шаг сборки как `VITE_ADMIN_PANEL_ENABLED: ${{ vars.VITE_ADMIN_PANEL_ENABLED }}`. Пока этого нет, флаг останется выключен. Проверять deployment только после подтверждения владельца.
7. Адрес первой версии: `https://ryadomcity.ru/#/admin` (hash-маршрутизация). Кабинет намеренно не связан публичной кнопкой меню. **Скрытая ссылка не является защитой** — доступ обеспечивает только Supabase RLS.

## Как это работает

- На сервере членство в таблице `city_admin_access` с ролями owner/editor. Не доверяем проверкам на уровне React.
- Admin сохраняет только разрешённые поля. Публикация требует подтверждения проверки сведений, а Supabase запрещает публикацию без `verified_at`.
- Черновики не видны гостям; архивирование скрывает их из публичного каталога (после включения DB-режима).
- Сайт показывает данные из базы, когда соединение успешно; при недоступности Supabase он показывает последнюю статическую базу из кода с предупреждением.
- Кнопка «Удалить» намеренно не реализована: архивирование безопаснее для избранного, истории и ссылок.
- Фото JPEG/PNG/WebP до 2 MB сохраняются в публичном бакете `ryadom-places` в папке города. Загрузка контролируется RLS Storage. Никогда не загружать документы, персональные данные или фото без разрешения правообладателя.
- Пока другой посетитель держит старую вкладку открытой, карточка обновится при следующем открытии/перезагрузке страницы. Возможность live-sync можно добавить позднее.

## Не перепутать с другими функциями

- `VITE_ORGANIZATIONS_ENABLED` — прежние заявки пользователей, пока не включать без отдельного тестирования.
- `VITE_ADMIN_PANEL_ENABLED` — новая админка для мест/услуг и чтение каталога из базы, только после ручной миграции.
- Все 17 новых статических карточек могут отображаться без миграции в сборке сайта; см. `docs/eniseysk-catalog-sources.md`.
- `SPRINTHOST_DEPLOY_ENABLED` — отдельный выключатель автоматической публикации через GitHub; никаких общих ключей с Supabase.
- Платёжная система, новости, афиша, партнёрские подписки и массовая модерация **не входят** в этот первый этап.

## Проверка безопасности

- Гость / обычный залогиненный: не видят черновики, не могут добавлять/редактировать/загружать фото.
- Editor города А не может править город Б.
- Owner управляет всеми городами, но не может создать другого owner через браузер (доступы выдаются через SQL).
- Публичный каталог содержит только `published`. При обновлении сохранённого места сохраняется исходный ID.
- Не выдавать Supabase `service_role`, `sb_secret_` или пароль Спринтхоста браузеру и GitHub исходникам.
