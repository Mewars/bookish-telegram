# Приложения «РЯДОМ» для iOS и Android — аудит исходного проекта

Дата анализа: 15.10.2026. Основа: рабочая ветка `mewars` репозитория `Mewars/bookish-telegram`, React 19 + TypeScript + Vite 7, Supabase.

**Статус:** только техническая подготовка. Android APK/AAB, Xcode-проект, TestFlight и приложения в магазинах **не созданы и не проверены**. Этот документ не разрешает преждевременный публичный выпуск.

## Что можно использовать повторно
- Имеющиеся страницы городского каталога, поиска, организаций, афиши, профиля и избранного, большинство стилистики и мобильной навигации.
- `src/hooks/useRoute.ts` использует хэш-маршруты `#/...`, что удобно для встроенной WebView при правильной обработке deep links.
- `src/lib/supabase.ts` уже создаёт SupabaseClient с PKCE, сохранением сессии и автообновлением токенов, но **хранилище и возврат OAuth в приложениях потребуют отдельной адаптации**.
- Отдельный флаг `VITE_CLASSIFIEDS_ENABLED` и жёсткая привязка беты к Ryadom-Test позволяют не выводить недоработанные объявления в релиз.

## Предлагаемый способ: Capacitor, после прототипа
**Первый кандидат**: Capacitor с двумя отдельными нативными проектами для Android/iOS, используя собранные статические файлы `Vite`. Не добавлять его в боевой `package.json` и не публиковать WebView-обёртку, пока не будут проверены условия ниже. PWA не заменяет запрос владельца о двух самостоятельных приложениях в магазинах.

Потенциальные изменения: `capacitor.config.ts`, отдельные native-скрипты сборки, `android/` и `ios/`, только публичная конфигурация Supabase. Для Android нужна Java/Android SDK и подпись релиза; для iOS — macOS, Xcode, настройка Team/Signing и доступ к реальным устройствам. В текущем GitHub CI подтверждён только веб-билд, **не** нативная сборка.

## Главные блокирующие факторы
1. **Авторизация.** `src/auth/oauth.ts` запускает Supabase web OAuth через `signInWithOAuth` и передаваемый `redirectTo`. В нативном приложении необходимо завершать вход во внешнем системном браузере, безопасно возвращать результат через Universal Links/App Links (либо тщательно проверенную альтернативу), не вставлять access/refresh token в URL, не терять PKCE state и корректно восстанавливать сессию. Проверить VK ID, Яндекс ID, email и отмену входа на каждом ОС. Пока этот пункт не решён, мобильную бету нельзя считать готовой.
2. **Базовые URL.** `vite.config.ts` формирует основной веб-сайт с `base: '/'`, а `index.html` содержит корневые абсолютные пути (`/src/main.tsx`, `/brand/...`). Для пакета Capacitor проверить работу локальных ресурсов и корректное открытие страниц без интернет-соединения. В частности не допустить обращения к веб-хостингу для стартовых JS/CSS по ошибке.
3. **Клиентские зависимости и безопасность.** В приложение нельзя включать `service_role`, OAuth client secrets, SSH, параметры деплоя и ключи приватных серверных функций. Публичный ключ `sb_publishable_` разрешён только при корректной RLS. Проверять разделение production/test.
4. **Навигация и поведение устройства.** Системная кнопка «Назад» Android, безопасные области iOS, клавиатура, поворот, доступность и увеличенный размер текста, открытие ссылок на внешние карты/организации, загрузка фото из галереи. Не допускать рекурсивных переходов при hashchange.
5. **Магазины и право.** Проверить актуальные требования выбранных магазинов, возможность публикации владельцем и применимость магазинов для России, privacy disclosures, регистрацию разработчика, подписи, модерацию и политику данных. Платежи (если появятся) потребуют отдельно проверить правила stores; сейчас не внедрять.
6. **Пуши/геолокация.** Не запрашивать разрешения при первом запуске без конкретной цели. Новая «Друзья на карте» — только после отдельного согласия, двусторонней дружбы, времени жизни координат и RLS; смотреть issue #85.
7. **Установочная графика.** Иконки и заставки сделать из утверждённого логотипа «РЯДОМ» без внешних шрифтов/несогласованных изображений; подготовить необходимую растровую сетку под платформы.

## План безопасной реализации
1. Создать **изолированную ветку native-prototype** без слияния в `mewars`. Протестировать минимальный запуск главной в Android emulator/физическом устройстве. Явно зафиксировать использованные SDK, версии и скриншоты.
2. Сделать безопасный OAuth adapter + нативное хранилище сессии, тесты на возврат из браузера. Не переделывать действующий web OAuth в этой задаче.
3. Добавить тестовый проект iOS и проверить на macOS/Xcode; без Mac только подготовить исходники, но не писать «iOS протестирован».
4. Проверить работу реальных фотографий, карт, справочника, профиля, избранного и **выключенность** закрытой беты объявлений.
5. Провести два варианта тестирования: устройства с малым экраном/медленным соединением и нормальные iPhone/Android; воспроизвести сценарии из рабочего сайта.
6. Подготовить внутренние сборки, установить их на устройства, проверить store compliance, privacy declarations и только затем отдельно согласовать выпуск.

## Критерий первого нативного MVP
Оба приложения устанавливаются, открывают конкретный город и основные разделы, сохраняют авторизацию и избранное, не демонстрируют веб-ошибок, не раскрывают токены и персональные данные, проходят ручные smoke-тесты **на реальных устройствах**, а production веб-сайт остаётся без изменений.
