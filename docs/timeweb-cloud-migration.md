# Переезд «Рядом» с GitHub Pages на Timeweb Cloud App Platform

Статус: **подготовка / без переключения DNS**. Исходный код: `Mewars/bookish-telegram`, основная ветка `mewars`.

## Почему этот вариант

«Рядом» — статический фронтенд React + Vite + TypeScript с hash-маршрутизацией. Timeweb Cloud App Platform (тип frontend → React) собирает проект из исходников GitHub и выдаёт бесплатный технический адрес с HTTPS для проверки до переключения `ryadomcity.ru`. В отличие от типа HTML/CSS/JS, для React не требуется коммитить `dist/` в репозиторий.

Важно: **регистрация домена и DNS у Timeweb не означают, что уже заказан платный хостинг Timeweb Cloud**. Наличие услуги, тариф, регион и возможные платежи проверяет и подтверждает владелец. Приложение в Timeweb Cloud из этой инструкции автоматически не создаётся.

## 1. Создать тестовую публикацию

1. Войти в **Timeweb Cloud** → **App Platform** → **Создать приложение**. Проверить условия тарифа перед оформлением. Это отдельный кабинет/продукт по отношению к обычному редактору DNS.
2. Выбрать **Frontend → React**, подключить GitHub, разрешив только нужный репозиторий, и выбрать `Mewars/bookish-telegram`. Альтернатива: публичный URL `https://github.com/Mewars/bookish-telegram.git` (при подключении по URL автоматические деплои могут быть недоступны).
3. Ветка: `mewars`. **Включение автодеплоя отложить** до проверки: вначале управлять публикациями вручную, чтобы новый коммит не менял сайт неожиданно.
4. Рабочая директория: корень репозитория. Node.js: **22**, если выбор версии доступен.
5. Команда сборки: `npm run build`. Установка зависимостей: `npm ci`, если платформа позволяет явно задать команду; иначе стандартный npm. Директория готовых файлов: `dist`. Для Timeweb не использовать `npm run build:pages:test`, т. к. там base `/bookish-telegram/`.
6. Для тестовой сборки задать локальные переменные приложения:
   - `VITE_SUPABASE_URL`: тот же публичный URL, что в действующей конфигурации.
   - `VITE_SUPABASE_PUBLISHABLE_KEY`: тот же **публичный** ключ вида `sb_publishable_…`.
   - `VITE_YANDEX_MAPS_API_KEY`: существующий публичный браузерный ключ, **если** используется встроенная карта; проверить ограничения доменов.
   
   Эти значения берутся владельцем из действующих настроек сборки, **не публикуются в GitHub, чате или PR**. Не добавлять `service_role`, `SUPABASE_SECRET_KEY`, OAuth client secret, Telegram Bot Token и пароли базы в клиентский проект.
7. В режиме тестирования **не задавать `CONTEXT=production`**, чтобы не вставлять noscript-пиксель Яндекс Метрики на технический домен. JavaScript Метрики уже ограничен origin `https://ryadomcity.ru`.
8. После запуска проверить технический домен Timeweb с HTTPS. **Не добавлять пока `ryadomcity.ru` и не менять DNS.**

## 2. Проверить сайт с российского подключения, без VPN

На техническом домене открыть с компьютера и iPhone:
- главную, hero/картинку, CSS, JS, иконку; в DevTools → Network нет ошибок загрузки;
- переходы через `/#/places`, `/#/events`, `/#/services`, `/#/profile`, `/#/login`, обновление страницы с hash;
- поиск, детали мест, Яндекс Карты, избранное (сохранение после reload), тему, музыку;
- cookie/согласия, юридические страницы, экспорт в локальном импортере; отсутствие неожиданной отправки данных импортера;
- авторизацию **только после** добавления точного технического URL в Supabase Auth Redirect URLs и проверки правил Яндекс ID. До этого можно проверить гостевой UI; редирект OAuth на непризнанный домен не должен считаться сбоем хостинга;
- доступ к Supabase/Auth **без VPN**: перенос только frontend в РФ не делает автоматически доступными внешние API и не переносит базу данных в РФ. Проверить запросы в Network отдельно.
- Telegram Mini App после cutover: HTTPS URL останется `https://ryadomcity.ru`, но работоспособность SDK и BackButton проверить отдельно.

**Критерий продолжения:** технический домен отвечает по HTTPS без VPN, загрузка основных ресурсов/экранов не даёт ошибок, критичные внешние API доступны или их ограничения зафиксированы. Иначе не выполнять cutover.

## 3. Подключить домен после проверки

1. Сохранить текущие DNS-записи и сделать скриншот. На 11.10.2026 по предоставленному снимку:
   - `ryadomcity.ru A 185.199.108.153`
   - `ryadomcity.ru A 185.199.109.153`
   - `ryadomcity.ru A 185.199.110.153`
   - `ryadomcity.ru A 185.199.111.153`
   - `www CNAME mewars.github.io`
   
   Это **записи для возврата к GitHub Pages**, не новые записи Timeweb.
2. В настройках готового App Platform → **Домены** указать `ryadomcity.ru`; платформа покажет нужный адрес и порядок настройки. **Не выдумывать A/CNAME заранее.**
3. В действующем DNS-редакторе Timeweb заменить 4 A-записи GitHub для корня на **конкретные значения, показанные Timeweb Cloud**. Для `www` использовать схему, выданную для `www` в настройках Timeweb; прежний `mewars.github.io` не оставлять при полном переходе. Не трогать MX/TXT/почту/NS и остальные сторонние записи.
4. Дождаться обновления DNS и выпуска HTTPS-сертификата для production-домена в Timeweb. Проверить `https://ryadomcity.ru/` и `https://www.ryadomcity.ru/` без VPN с разных сетей. Проверить сертификат и отсутствие HTTP-ошибок.
5. После подтверждения — проверить OAuth callback/PKCE, email links/пароль, авторизацию и избранное на production, Яндекс Карты, Метрику при согласии, Telegram Mini App.
6. Только когда новая площадка стабильно работает, решить, отключать ли **автодеплой GitHub Pages**, Netlify и тестовые площадки. Хранение исходного кода в GitHub не меняется. Не отключать раньше как механизм отката.

## 4. Откат при проблемах

Если после cutover сайт перестал открываться, вернуть сохранённые старые A/CNAME-записи GitHub или другой подтверждённый рабочий hosting origin. Подождать DNS-кеш и повторно проверить HTTPS на выбранной площадке. При этом не изменять NS. Сохранённые настройки Supabase / OAuth не удалять до восстановления.

## 5. Что **не** делает этот PR

- Не покупает сервис Timeweb Cloud и не создаёт приложение.
- Не меняет DNS, GitHub Pages, Netlify, Supabase/Auth/RLS, secrets и production.
- Не подтверждает доступность технического домена (он ещё не создан).
- Не переносит Supabase и внешние API в Россию.
- Не включает массовый автодеплой без согласия владельца.

Первое действие владельца: определить, есть ли уже оплаченная услуга для размещения сайта в Timeweb (обычный веб-хостинг, VPS или Timeweb Cloud App Platform) и прислать скриншот соответствующего раздела **без ключей, паролей и токенов**. Дальнейший путь зависит от этой информации.
