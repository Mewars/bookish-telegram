# Тема до первого отображения

Раньше пустой HTML не задавал фон, а основной CSS включал светлую тему до эффекта React. Теперь синхронный скрипт в начале head устанавливает data-theme до загрузки CSS и JavaScript приложения. Минимальные встроенные стили задают фон html/body, цвет текста и color-scheme из существующих дизайн-токенов.

Ключ ryadom.theme принимает JSON-строки и обычные light/dark/system. Отсутствующие, повреждённые или неизвестные значения и недоступный localStorage означают system; системная тема определяется prefers-color-scheme. React использует такой же reader, чтобы обычное значение dark не сменялось системной светлой темой после запуска. Запись остаётся в существующем JSON-формате. Ранняя установка не записывает localStorage.

Загрузчик PR #32, исходный SVG, анимация, обработка ошибок, тайм-аут 20 секунд и маршруты не изменены. Новых задержек, запросов, зависимостей или загрузочных элементов нет. Telegram после загрузки SDK продолжает применять свою системную схему по существующим правилам.

## Проверки

- npm ci --ignore-scripts, npm run lint, npm run build, npm test: успешно, 84 теста, включая 29 новых проверок раннего скрипта и React-reader.
- Production-сборка, Chromium/Playwright: 30 сценариев первого открытия в новом контексте без кеша и повторной загрузки. Размеры 1440×900, 320×568 и 390×844; мобильная эмуляция с touch.
- Светлая/тёмная/system, JSON и обычные значения localStorage, пустое и повреждённое значение. До разрешения запросов JS/CSS root остаётся пустым, data-theme и вычисленные фоны html/body уже корректны. После запуска и повторного открытия тема сохранена.
- Кадры requestAnimationFrame от первого отображения до готового интерфейса: в тёмных сценариях фон html и body остаётся rgb(7,22,34), светлых кадров нет.
- При задержке публичного модуля сохраняются app-pin-bounce и период 1,2 секунды. Продвижение тестовых часов до 20 секунд показывает прежнюю ошибку; кнопка перезагрузки восстанавливает интерфейс после разрешения запроса.
- Нет необработанных JS-ошибок в матрице тем. Ошибки storage и отсутствие matchMedia дополнительно покрыты unit-тестами.
- WebKit/Safari и физические мобильные устройства недоступны; мобильные проверки выполнены Chromium.

Проверки выполнены локально. Merge и production deployment не выполнялись.
