# Рядом — закрытый редактор фотографий карточек

**Готов код, Supabase миграция пока не применена.** Текущий каталог содержит 25 статических карточек. Не нужно ждать полного запуска организации/CMS: редактор фото использует отдельную таблицу `directory_card_photos` и отдельный публичный Storage bucket `ryadom-card-photos`.

## Что умеет

1. Войти в «Рядом» под настоящим аккаунтом администратора.
2. Открыть `https://ryadomcity.ru/#/photo-admin` или ссылку из профиля.
3. Найти организацию Енисейска по названию или адресу.
4. Выбрать её карточку и настоящее фото с компьютера или телефона.
5. Увидеть предварительный просмотр, подтвердить разрешение на размещение, нажать «Сохранить фотографию».
6. Фото автоматически уменьшается до 1600 × 1200, конвертируется в WebP в браузере, очищается от EXIF и GPS, загружается в Supabase Storage, а путь сохраняется в таблице. Посетители видят картинку при следующей загрузке сайта без GitHub.
7. Можно заменить/убрать фото, при отсутствии остаётся собственная заглушка или ранее согласованный снимок монастыря.

**Никаких стоковых фотографий для конкретных организаций.** Нет загрузки чужих фото из 2ГИС/VK.

## Почему не включено прямо сейчас

Supabase Free не даёт автоматических резервных копий. 14.10.2026 работающая база содержит Auth, profiles, user_identities, user_favorites; отдельная проверенная локальная копия ещё не была создана. Ради данных пользователей нельзя запускать неподтверждённую миграцию в production.

Кроме того, владелец ещё **не подтвердил UUID нужного аккаунта** в Supabase Auth. Нельзя наугад назначить роль `owner` любому из 3 аккаунтов. Пароль, service_role key, cookie, SSH private key для этого не нужны и не должны отправляться в чат.

## Порядок включения без потери данных

1. Получить резервную копию `pg_dump` с компьютера владельца (инструкция: `docs/supabase-backup-windows.md`). По возможности проверить восстановление отдельно.
2. Убедиться в правильности будущего владельца: войти на сайт через Yandex/VK или другой настроенный способ, открыть `/#/photo-admin` после включения или посмотреть собственный Auth User UID в Supabase Dashboard. Проверить UID вне публичного чата. Никаких прав по имени или e-mail.
3. На тестовом экземпляре применить `docs/sql/directory-photos-admin.sql`, проверить guest RLS, unknown authenticated, editor, owner, запрещённые MIME-типы/пути, отсутствие доступа к чужим городам. В репозитории есть автоматические PGlite тесты `npm run test:photo-editor`, но они **не заменяют** live Storage test.
4. После проверки выполнить **отдельную** аддитивную миграцию на production и вручную назначить проверенный UUID владельца. Файл SQL содержит комментированный шаблон назначения. Он не меняет существующие Auth, profiles, favorites и не создаёт таблицу организаций.
5. В GitHub Actions Repository Variables создать `VITE_CARD_PHOTOS_ENABLED=true`. **НЕ** менять `VITE_ADMIN_PANEL_ENABLED`, поскольку полноценная CMS организаций требует другую миграцию и бэкап.
6. Запустить workflow Deploy Ryadom to Sprinthost или дождаться следующего изменения в `mewars`, проверить `/#/photo-admin`, 1 настоящую фотографию и публичную карточку на iPhone. При необходимости выключить фотоадминку, изменив переменную обратно в `false` и повторив деплой.
7. На бесплатном Supabase контролировать Storage объём. Старые версии изображений могут остаться в bucket при ошибках связи; они не отображаются, но могут занимать место.

## Безопасность

- Серверные RLS-политики: гости только читают таблицу фото; `INSERT/UPDATE/DELETE` разрешены исключительно назначенным администраторам `city_admin_access` в городе Енисейск или владельцу scope `*`.
- Storage: bucket `ryadom-card-photos`, серверный лимит 4 MiB, `image/webp` только; путь `eniseysk/card-id/uuid.webp`. SVG/HTML нельзя загружать.
- Браузер: проверяет `auth.getUser`, MIME, размер исходника, делает WebP-кодирование и превью, после записи уведомляет всех пользователей на текущей вкладке. Это UX и дополнительная проверка, **не замена RLS**.
- Никому не выдавать `service_role` или SQL Editor на основании нажатия кнопки «Админ».
- Пока организация не добавлена в настоящую таблицу Supabase, редактирование остальных данных и загрузка фото для неё работают **независимо**.

## Технические файлы

- `src/photos/PhotoAdminPage.tsx`: мобильный интерфейс.
- `src/photos/directoryPhotos.ts`: оптимизация, загрузка, удаление, публичные URL и валидация.
- `src/photos/useDirectoryPhotos.ts`: накладывает фотографии на 25 исходных карточек.
- `docs/sql/directory-photos-admin.sql`: безопасный план миграции (НЕ выполняется автоматически).
- `tests/directory-photos-rls.test.mjs`: отдельные серверные проверки SQL через PGlite.
