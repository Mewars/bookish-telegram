## Браузер

Локальные Vite development и production preview проверены Chromium/Playwright. Форма и статусы проверены с имитацией Supabase, без реальных входов или записей в БД:

- Пустые поля, обязательное отдельное согласие, недопустимый URL, сетевой отказ, доступность повторной отправки и подтверждение `pending`.
- Пустой список, pending/approved/rejected, ссылка на одобренную карточку, ошибка чтения списка, повторная попытка.
- Переход из каталога и профиля; гостевое ограничение. Выход/смена аккаунта очищает интерфейс предыдущего заявителя.
- Недоступность Supabase сохраняет 10 локальных мест.
- Новые форма/список/согласие: 36 комбинаций трёх экранов, шести ширин (320, 375, 390, 430, 768, 1440 px) и двух тем. Горизонтальной прокрутки и ошибок JavaScript нет.
- Обычная production-сборка с флагом OFF: 168 комбинаций существующих экранов, тех же ширин и двух тем; поиск, категории, избранное с перезагрузкой, навигация, профиль/вход, согласия, карты, музыка, локальный CSV-importer. Ошибок JavaScript и горизонтальной прокрутки нет.
- OFF: кнопки новой функции скрыты, прямые новые маршруты показывают отключённое состояние, запросов к новым таблицам нет.
- ON без Supabase: гостевое предложение войти, локальный каталог остаётся доступен.

390 px — проверка размера viewport iPhone 13 в Chromium, **не проверка реального iPhone или Safari**. Такая проверка остаётся в ручном чеклисте перед включением.

## SQL

`tests/organizations-rls.test.mjs` устанавливает SQL только в изолированную временную PGlite/PostgreSQL базу. Проверены original seed IDs и повторный seed, гостевые права, RLS на чужие заявки, pending по умолчанию, запрет клиентского изменения статуса/публикации/повышения роли, согласие, длины, координаты, уникальность и атомарность административной публикации при успехе/ошибке.

**На настоящем Supabase миграция не устанавливалась.** Проверка с реальными тестовыми JWT/PostgREST, аккаунтами A/B и существующими политиками обязательна перед включением: см. [organizations-setup.md](organizations-setup.md). Продакшен HTTPS, реальная отправка заявок и действующие OAuth callback не проверялись этой имитацией.

Netlify Preview выпускается штатным PR-процессом, с флагом OFF. Доступ к доменам Netlify из рабочей среды ограничен; успешный статус deployment на GitHub не заменяет ручную проверку опубликованного Preview владельцем. Что проверить без новой базы и как включить только после согласования, описано в инструкции запуска.
