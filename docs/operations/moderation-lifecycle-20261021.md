# Повторная отправка и проверка модерации

В действующих самостоятельных модулях объявлений и стены созданный черновик раньше не запоминался формой. Если файл или отправка на модерацию завершались ошибкой, повторное нажатие создавало ещё одну запись. Успешно загруженные файлы при повторе также могли добавляться снова.

Теперь форма повторно использует ID своего созданного черновика и пропускает файлы, которые уже успешно загрузились в этой форме. Непрошедший файл загружается повторно. Подмена города и автора не разрешается: обновление использует существующий защищённый механизм, публикация остаётся через модерацию. После отказа причина также видна непосредственно в «Моих объявлениях», до открытия редактора.

Проверка tests/local-e2e/host-moderation.py соединяет реальные самостоятельные интерфейсы с одноразовыми локальными Auth, PostgreSQL, PostgREST и Storage. SDK собирается из установленной по lockfile зависимости; код интерфейсов не заменяется имитацией SDK. Внешняя сеть браузера заблокирована: адрес production в исходниках перехватывается и обслуживается через loopback. Сервисный ключ тестовой установки не передаётся браузеру. Шесть синтетических аккаунтов создаются только в одноразовой установке. Production и Ryadom-Test не изменяются.

Сценарии: сбой второй фотографии, затем сбой отправки; один ID после повторов, две фотографии без повторов; закрытые черновики и очередь; отказ чужому городу и обычному жителю в модерации; отказ без причины; отклонение через интерфейс городского редактора; причина автору; исправление; одобрение владельцем; публичная лента только выбранного города; владелец может проверять собственную запись, городской редактор — нет.

tests/local-e2e/host-schema содержит копии недостающих в репозитории исторических SQL-миграций стены и типов объявлений, прочитанные из production 21 октября. Они используются исключительно для воспроизведения изолированной установки; их нельзя повторно применять к облачным проектам. Последний патч community-review-reasons-v1.sql применяется после них и требует проверки всех записей, независимо от старого режима open.

Эта проверка подтверждает интерфейс и серверные ограничения в воспроизведённой установке. Она не является входом реальных пользователей через VK/Яндекс на телефонах, не проверяет почтовую доставку и Web Push.

Дополнительно 21 октября через системные каталоги Production/Test проверены без изменений данных: RLS включена на classifieds, classified_moderation_history, community_posts, community_post_review_reasons и city_admin_access; шесть функций создания, отправки, отзыва и модерации недоступны anon. Определения этих функций совпадают в обеих базах. Это проверка конфигурации, а не запись тестовых материалов в Production.
