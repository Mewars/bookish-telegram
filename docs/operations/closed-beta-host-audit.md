# Проверка защищённого HTTPS-хоста закрытой беты «РЯДОМ»

**Статус на 15.10.2026:** добавлен только аудит размещения. Защищённого beta-host и реального бета-адреса пока нет; этот workflow **никогда ничего не развёртывает**.

## До ручного аудита

1. Выбрать **отдельный поддомен** вида `https://beta.ryadomcity.ru` (конкретное имя должно быть согласовано). Не размещать бета-сборку в `ryadomcity.ru/public_html`, не менять действующие production-пути. Хостинг/прокси настраивается **отдельно**.
2. Включить HTTPS с валидным сертификатом, HTTP Basic Auth **на уровне сервера** для **всех** файлов, включая `/index.html`, `/assets/`, `/robots.txt`, `/version.json` и отсутствующие пути. Ответ постороннему: **401** или **403**, а не перенаправление и не HTML. Успешная проверка Basic Auth не заменяет права Supabase.
3. Исключить кеширование авторизованного HTML (заголовок `Cache-Control: no-store`).
4. Развернуть **только** ZIP из ручной упаковки `Closed Beta Package (not a deploy)` со строгим backend `Ryadom-Test`, после подготовки отдельной test Auth конфигурации. Сборка `version.json` должна содержать полный SHA коммита, соответствующий ZIP. Отсутствующий/чужой артефакт — отказ.
5. Установить только **GitHub Actions Secrets** `RYADOM_BETA_BASIC_USER` и `RYADOM_BETA_BASIC_PASSWORD` для проверки тестового хоста. **Пароли никогда не передавать в чат и не добавлять в URL, команды, код или файлы репозитория.** Эти учётные данные не являются учётными данными Supabase и не предназначены для публичного сайта.

## Автоматический аудит

После настройки хоста вручную запустить workflow `Closed Beta Host Security Audit (manual, never deploy)` из ветки `mewars` с полями:

- `beta_origin`: точный HTTPS origin отдельного beta-поддомена, без пути и параметров;
- `expected_sha`: полный SHA коммита **реально загруженного beta ZIP**.

Сценарий `scripts/audit-closed-beta-host.mjs` проверит:
- отказ без HTTP Basic Auth для корня, index, robots, version, известного брендинга, несуществующего asset и **реального** JS и CSS из HTML;
- отказ для двух неверных комбинаций Basic Auth: неправильного имени и неправильного пароля;
- отсутствие перенаправлений, которые могли бы переслать Basic Auth в другое место;
- доступность корня, JS и CSS с правильным доступом и наличие `Cache-Control: no-store` у HTML;
- бета-теги `noindex`, отсутствие canonical, `robots.txt` с `Disallow: /`;
- точный SHA `version.json` и отсутствие production backend ID в полученном HTML/entry JS/CSS, корректный MIME-тип CSS и отсутствие известных маркеров секретов в CSS.

Изолированные тесты функции выполняются в PR без сетевых запросов. Проверка настоящего адреса запускается **только вручную**, не во время PR, не по расписанию и не выполняет публикацию/изменение DNS, хостинга или базы.

**Ограничение:** проход этой проверки **не** подтверждает права RLS, содержание всех chunks JavaScript, доступность Supabase Auth, выдачу/получение email, E2E между пользователями, разрешённость обработки персональных данных в зарубежном регионе или готовность к релизу. Все эти проверки нужны отдельно; требования локализации и юридическая оценка выполняются **до** работы с реальными персональными данными.
