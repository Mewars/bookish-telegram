# Закрытая бета «РЯДОМ»: изолированная сборка и условия запуска

**Дата:** 15.10.2026. **Статус:** инфраструктурная подготовка, **не опубликована**.
Рабочий сайт `https://ryadomcity.ru` и production Supabase `cptbmepnbzogqkfhflsg` не изменяются данным механизмом.

## Сборка и защита от ошибочного подключения

1. `npm run build:beta` запускает предварительный fail-closed аудит, Vite в режиме `closed-beta`, затем проверяет готовые файлы.
2. Допускается **только** URL `https://djqhixvlfsbvannoqdjw.supabase.co` (Ryadom-Test). Произвольные пути, чужие домены или production отбрасываются.
3. Ключ для браузера должен быть **только публичным** `sb_publishable_…` от Ryadom-Test. Нельзя использовать `service_role`, `sb_secret_…` или старый JWT.
4. Обязательные переменные: `CONTEXT=closed-beta`, `VITE_CLASSIFIEDS_ENABLED=true`, `VITE_COMMUNITY_ENABLED=true`, `VITE_BETA_EMAIL_ONLY=true`. VK ID и Яндекс ID в beta-сборке отключены; админка каталога, редактирование фото каталога, каталог организаций и управление городами тоже отключены для предотвращения неверных записей.
5. На beta HTML устанавливаются `noindex,nofollow,noarchive,nosnippet`, `no-referrer`; убираются canonical ссылки и JSON-LD сайта; `dist/robots.txt` заменяется на `Disallow: /`. Это **не защита доступа**.
   - Проверка содержимого ZIP теперь рекурсивно проверяет все текстовые файлы сборки, включая вложенные JS chunks, CSS, JSON и SVG: в них не должно быть идентификатора production Supabase, серверных ключей или незаменённых переменных конфигурации. Отсутствие этих строк **не доказывает** безопасность всех внешних API или RLS.
   - Синтетические регрессионные тесты для вложенных ресурсов запускаются через `npm run test:beta-config` и PR smoke. Положительный CI не означает, что настоящий тестовый HTTPS-хост создан.
6. Workflow `Closed Beta Package (not a deploy)`:
   - В PR автоматически проверяет сборку со **специальной НЕрабочей** тестовой строкой ключа; ничего не публикует и не загружает.
   - По ручному запуску из `mewars` использует **только** GitHub Secret `RYADOM_TEST_SUPABASE_PUBLISHABLE_KEY` (должен быть установлен) для настоящей сборки, тестирует проект и сохраняет ZIP как закрытый GitHub Actions artifact на 7 дней.
   - **Никогда не** выкладывает ZIP на рабочий Sprinthost, GitHub Pages или неизвестный хост.

## Что необходимо проверить до открытия адреса семье

- Отдельный DNS-адрес и независимый каталог/хостинг **вне** `ryadomcity.ru/public_html`. HTTPS, парольная защита на **сервере/реверс-прокси** (например HTTP Basic Auth у nginx), отключённое кеширование приватных страниц и запрет поисковым роботам; нельзя полагаться на секретный путь, JavaScript-пароль или `robots.txt`.
- Провести тест внешнего HTTP-доступа: без правильных серверных учётных данных все страницы и ресурсы беты возвращают отказ; невозможен доступ к API от чужой учётной записи через RLS. Отдельная защита пользователей БД остаётся обязательной даже при сетевом пароле.
- Настроить **отдельные** Supabase Auth Site URL и Allowed Redirect URLs Ryadom-Test для утверждённого beta origin. Не менять VK/Яндекс OAuth в production. Проверить доставку подтверждения email и сброса пароля; поломка IMAP Sprinthost не доказывает работоспособность или неработоспособность встроенного отправителя Supabase.
- Сверить настоящие права редактора тестового города после создания пользователя (пока `auth.users=0` и `city_admin_access=0`). Не создавать пользователей по фиктивным именам/UUID в публичной системе и не назначать права по совпадению отображаемого имени. Участники тестирования: владелец + жена **или** брат со своими отдельными учётными записями. Не присылать пароли в чат.
- Требования о локализации персональных данных граждан РФ и тексты политики/согласия оценить и выполнить **до** работы с реальными персональными данными на инфраструктуре `eu-west-1`; сам статус «бета» не отменяет эти требования. До этого использовать только синтетические данные в изолированных автоматических тестах.

## Реальные проверки перед приёмкой

1. Заявка автора: черновик → редактирование → 1–10 фото → отправка на модерацию.
2. Редактор другого аккаунта: отклонение/одобрение; запрет самопубликации и межгородской модерации.
3. Покупатель: отправка сообщения автору, отображение у обоих, отметка прочитанного, подгрузка ранних сообщений.
4. Отдельный третий аккаунт: не видит чужие черновики, переписки, неопубликованные фото и очередь жалоб.
5. Блокировка отправителя, жалоба, снятие объявления с публикации, недоступность скрытых фото; проверка фактического истечения ссылок на фото.
6. Городская лента: создание и модерация записи/комментария, городские роли, скрытие. VK интегрировать только после проверки официальных прав и API.
7. Полная проверка на ноутбуке, Safari iPhone и Android. Автотесты Chromium не равны проверке физических устройств.

**Блокер:** пока нет подтверждённого и защищённого beta-host, настроенного email/Auth, допустимого правового основания для обработки реальных данных и двух тестовых учётных записей. ZIP — лишь проверенная заготовка для закрытого развёртывания.
