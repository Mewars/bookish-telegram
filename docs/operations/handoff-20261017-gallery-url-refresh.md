## Изменения

Галерея обновляет подписанные на 600 секунд ссылки после 540 секунд от начала
подписания. Возврат видимости/фокуса проверяет срок сразу, даже если таймер
фоновой вкладки задержался. Пустой альбом не опрашивается; ошибка останавливает
автоматические повторы. Выбранный снимок сохраняется при обновлении URL.
Ошибка основного изображения или миниатюры показывает ручное восстановление
и блокирует редактирование до успешного перечитывания альбома. Очистка эффекта
отменяет таймер и снимает слушатели.

## Проверки

8 сценариев в настоящем Chromium на реальном React-компоненте: два цикла
обновления, сохранение выбранного снимка, возврат видимости, возврат фокуса,
пустой альбом, ошибка запроса + ручной повтор, ошибки главного снимка/миниатюры,
отмена таймеров/слушателей при unmount (связанные проверки объединены в сценарии).
Время ускоряется Playwright Clock; Storage явно подменён fixture-модулем.
Это браузерная регрессия компонента, НЕ живой многоаккаунтный Supabase E2E.

Запуск: node tests/browser-gallery/server.mjs; отдельно python
 tests/classified-gallery-browser.py. Для установленного системного Chromium
задать PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium. CI ставит закреплённый
playwright==1.62.0 и Chromium в отдельном workflow Classified Gallery Browser Regression.
В приложение не добавлены зависимости тестового браузера или обход backend gate.
Локальные npm test, lint и TypeScript/Vite build прошли.

## Изоляция и следующий этап

Production БД/Auth, DNS, секреты, RLS/Storage, время жизни URL и флаги выпуска
не меняются. Тестовый server слушает только 127.0.0.1 и использует синтетические
данные. Фактические PR/merge/CI/deploy сверять по GitHub и финальному handoff PR.
Следующий этап — локальный Supabase Auth/PostgREST/Storage и отдельные
синтетические пользователи A/B/C: это позволит проверить HTTP/RLS/Storage,
не ожидая настройки публичного beta-host и не используя реальные ПД.
Публичный HTTPS beta-host и семейная приёмка остаются отдельными воротами.
