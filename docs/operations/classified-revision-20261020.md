# Объявления: повторное редактирование и модерация

Основа: `mewars`, `1ac29574ca369571dcb98469a9a9f943eaec49ef`.
Изменения подготовлены для проверки; на серверы Supabase не применялись.

## Поведение

- В «Моих объявлениях» у опубликованного объявления автора появляется «Снять и изменить».
- После подтверждения сервер переводит только собственное опубликованное объявление в черновик. Содержимое и фотографии сохраняются. Форма открывается только после успешного ответа сервера.
- Черновик можно исправить, изменить фотографии и отправить на повторную проверку. До нового одобрения объявление отсутствует в публичном списке.
- RLS для прямого UPDATE опубликованного объявления не расширяется. Новый RPC принимает только ID и проверяет `auth.uid()`, автора и текущий статус на сервере. Запреты на смену автора, города и самостоятельную публикацию жителем сохраняются.
- Интерфейс учитывает активную роль `owner` с `city='*'`: глобальный владелец видит действия модерации и для собственных заявок. Городской редактор не одобряет себя и не управляет другим городом.

## Проверки и ограничения

Тесты PGlite запускают PostgreSQL с синтетическими пользователями: аноним, автор, покупатель, посторонний, редакторы двух городов, глобальный владелец. Проверяются отказ для чужих/неопубликованных/повторных операций, скрытие черновика и фото, повторная отправка, ограничения городов, запрет самостоятельной публикации жителем и редактором, отзыв роли владельца и история модерации. Проверка владельца включает третий условный будущий город.

Storage проверен на уровне политик и метаданных, без настоящих файлов. Ранее выданная подписанная ссылка на фото может работать до истечения текущего срока 600 секунд; этот механизм не изменён.

Это не проверка с реальными аккаунтами через браузер. Прямые HTTP-запросы из рабочей среды к ryadomcity.ru завершились тайм-аутом; расхождения опубликованного frontend с GitHub не установлены. Точная причина сообщения владельца «Недостаточно прав…» в действующей сборке поэтому ещё не доказана. В исходниках найден и исправлен конкретный отсутствующий сценарий редактирования опубликованного объявления.

## Условия выпуска

1. До merge сравнить действующие файлы Sprinthost с GitHub. `App.tsx` в исходной ветке по-прежнему ограничивает объявления тестовым backend; данный PR эти переключатели не меняет. Нельзя просто развернуть эту сборку поверх ручных исправлений на хостинге.
2. После согласования владельцем применить `docs/sql/classified-revision-v1.sql` сначала в Test и проверить RPC через Auth/Data API, фото и полный цикл на тестовых аккаунтах.
3. Применение SQL к Production, merge и deployment требуют отдельного разрешения владельца. В PR находится лишь подготовленный SQL. Новый frontend требует наличия `begin_classified_revision` на выбранном backend.
4. Перед публикацией проверить сценарии автора, городского редактора и глобального владельца на телефоне и компьютере.

Следующая критическая задача — безопасная кнопка возврата и сохранение фильтров публичного каталога. Она не включена в этот PR. Остальные шесть пунктов задания также не считаются выполненными.
