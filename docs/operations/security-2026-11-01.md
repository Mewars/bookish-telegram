# Security baseline — 2026-11-01

Scope: repository review, production Supabase advisory and table metadata reads, and a single HTTP header probe. No load testing, penetration test, account-setting changes, DNS changes or paid service activation.

## Implemented

- Security workflow: npm locked-dependency audit fails on high/critical advisories; CodeQL JavaScript/TypeScript security-extended scan on pull requests, production pushes and weekly. Actions pinned to reviewed commit SHAs; no production credentials supplied.
- Dependabot weekly pull requests for npm and GitHub Actions targeting `mewars`. Updates require review; no auto-merge.
- Managed Apache security block preserved across normal and maintenance deployments: no directory listing, deny sensitive file extensions and environment files, nosniff, same-origin framing, cross-origin referrer minimization, and CSP restrictions on objects, base URLs and framing. This is a limited CSP, not a full script policy or XSS guarantee.
- Real Apache regression coverage checks protected files return 403, headers are present and reopening still works.

- Updated the transitive development-only Zod dependency from 4.6.5 to 4.6.7 after npm identified GHSA-mrhx-c7xc-m3w5. This is not evidence of an exploitable production endpoint. Moderate development dependency advisories remain; no forced downgrades or broad upgrades were applied.

## Observed, not a complete assurance

- All 31 public production tables have RLS enabled. This alone does not prove every policy is correct.
- Supabase reports five internal tables with RLS and no policies (deny by default), seven anonymous-callable and 51 authenticated-callable SECURITY DEFINER functions. Many are intentional application APIs; do not revoke them in bulk. Each function's authorization and returned data require separate review.
- Supabase reports leaked-password protection disabled. Account capability, price and authentication impact must be checked before enabling; not changed here.
- Existing Friends host handler validates identity against Auth, limits request bodies and applies action limits. Weather gateway uses a fixed city/provider allowlist, bounded response and shared cache. Neither is an edge DDoS filter.

## Still required outside this patch

1. Confirm Sprinthost account's actual DDoS plan and application-layer HTTP flood protection, not only network-level filtering. Ask about WAF/rate limits, coverage of API paths, billing/attack limits and origin bypass. Do not change DNS or purchase a plan without the owner choosing it.
2. Verify owner MFA and recovery for GitHub, domain registrar, hosting and database accounts. This patch does not inspect or change these account settings.
3. Review SECURITY DEFINER functions and run role-specific authorization tests against an isolated database. Keep private messages, location sharing and admin actions in scope.
4. Verify independent backup restoration, monitoring and incident contact. Existing deployment archives are not a complete database backup.
