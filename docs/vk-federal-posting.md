# Федеральная VK-группа РЯДОМ: безопасное подключение публикаций

Дата: 17.10.2026. ID **242202919** сообщил владелец проекта как `club242202919`.
Ссылка на сообщество: https://vk.ru/ryadomcity; адрес публикаций `https://vk.ru/wall-242202919_<post_id>`.
Совпадение короткого адреса и числового ID через публичное VK API **ещё не подтверждено**; перепроверить в управлении группой до выдачи токена.

## Сделано в коде

- Записаны `FEDERAL_VK_COMMUNITY.id=242202919` и `wallOwnerId=-242202919`.
- Серверная Edge Function `vk-federal-publish` с точным `owner_id=-242202919` и `from_group=1`.
- Обязательная проверка JWT через Supabase Auth и роли `city_admin_access.city='*',role='owner',active=true`. Редактор отдельного города и гость не могут проверять секретный ключ или отправлять федеральные посты.
- Ограничение текста 20–2500 символов, запрет выбора произвольного сообщества, явное подтверждение публикации в интерфейсе владельца. Форма отдельная и не публикует объявления жителей или личную переписку.
- VK токен берётся **только из секретов Edge Function**, передаётся методом POST в тело серверного HTTPS-запроса к VK API; в браузер и клиентский JavaScript не попадает, ошибки VK не возвращают токен.
- Есть безопасный режим `action:check`: сервер вызывает `groups.getTokenPermissions` с сохранённым ключом и проверяет наличие права `wall`, **не создавая запись во ВК**. Он проверяет область разрешений ключа, но не доказывает, что ключ выпущен именно для сообщества `242202919` — это подтвердит только первый согласованный пост.
- `guid` равен UUID попытки, сохраняющемуся у клиента при неопределённом результате, но **долговременного журнала идемпотентности в БД пока нет**. Автоматический повтор запрещён.

## Не включать до авторизации VK

Обе функции выключены по умолчанию и должны включаться раздельно:

1. В Supabase Secrets федерального **production** проекта установить `VK_FEDERAL_GROUP_ACCESS_TOKEN` только с требуемым для публикации `wall` и разрешениями именно этой группы. Не путать с токеном VK ID, OAuth bridge и персональными ключами! **Никогда не присылать токен в чат, репозиторий или VITE_ переменную.**
2. Проверить метод выдачи токена через актуальные настройки API ВКонтакте и применимость данного типа токена к `wall.post`. У разных методов (например, загрузки фото) поддержка community token отличается, поэтому пока поддерживается только текст.
3. Развернуть Edge Function `vk-federal-publish` с `verify_jwt=true`, но изначально `VK_FEDERAL_POSTING_ENABLED=false`. Проверить 401/403 для гостя, другого пользователя и редактора города, 503 без секрета. Убедиться, что `SUPABASE_URL` и `SUPABASE_ANON_KEY` доступны только окружению функции.
4. Фронтенд-флаг `VITE_VK_FEDERAL_POSTING_ENABLED=true` теперь включает **только форму владельца**, где кнопка «Проверить подключение ВК (без публикации)» проверяет ключ на чтение. `VK_FEDERAL_POSTING_ENABLED` на сервере остаётся выключенным, поэтому публикацию сервер отклоняет даже при успешной проверке `wall`. Владелец должен проверить результат из кабинета на своём аккаунте.
5. Если проверка ключа и авторизации прошла, владелец отдельно добавляет серверный секрет `VK_FEDERAL_POSTING_ENABLED=true` (не VITE_) в Supabase Edge Functions → Secrets. После повторной проверки интерфейс позволит создать первую **явно подтверждённую** текстовую публикацию. Проверить `post_id`, ссылку и автора записи на стене; только после этого считать публикации подключёнными. Сейчас никаких публикаций не отправлено.

## Ограничения

- Произвольные объявления жителей, городские новости и чужие материалы не направляются в федеральную группу автоматически. Городские группы пока отсутствуют.
- Нельзя считать числовой ID подтверждением наличия разрешений API. Полномочия администратора в интерфейсе ВК не равны наличию работающего API-ключа.
- Первая версия серверной функции уже развёрнута в рабочем Supabase с `verify_jwt=true`; режим проверки требует отдельного обновления этой функции. Область разрешений созданного ключа пользователь ещё не проверял через сайт. Публичный сайт «РЯДОМ» и VK ID не должны зависеть от результатов проверки.
- Перед боевым запуском желательно добавить серверную таблицу аудита/идемпотентности публикаций с возможностью просмотра статусов: создано, отправлено, подтверждено, ошибка. В текущей версии есть только публичная ссылка в ответе VK при успехе.
