# Афиша ВК и российский календарь

Источники афиши заданы в `data/afisha-sources.json`: rodinaenis, gdk_e,
kulturnyy.centr. Город привязан к источнику, а не к городу посетителя.
Добавление будущего города — новая запись в общем справочнике источников.

## Реальный доступ к ВК

Сборщик использует официальный `wall.get` (filter=owner, count=100, v=5.199).
Нужен **сервисный или пользовательский ключ доступа**, которому ВК разрешает
чтение этих открытых стен. Секрет GitHub Actions: `VK_AFISHA_ACCESS_TOKEN`.
VK ID client_secret, пароль аккаунта и обычный ключ сообщества для отправки
постов не считаются автоматически подходящими ключами чтения чужих стен.
Ключ не хранится в репозитории, клиентском коде, JSON-ленте или журналах.

Без ключа отчёт явно сообщает `not_configured`. Это не успешное подключение
ВК. Если API отклоняет ключ, отчёт сообщает `unavailable`; прежняя лента не
перезаписывается. Сырой HTML ВК, браузерные cookies и обходы ограничений не
используются.

## Что попадает в афишу

Только собственные публикации указанных организаторов: анонс события с
фотографией, однозначной датой и временем. Исключаются репосты, рекламные
записи, поздравления, фотоотчёты, прошедшие события и сообщения об отмене
или переносе. Фотографии скачиваются только с разрешённых доменов ВК;
проверяются размер и сигнатура JPEG/PNG/WebP. Они хранятся локально, поэтому
клиент не зависит от временной ссылки на изображение.

Поддержаны одна дата или диапазон в одном месяце, а также дата ДД.ММ.ГГГГ.
Когда год в анонсе отсутствует, он определяется относительно даты публикации:
должна существовать ровно одна будущая дата в пределах 120 дней. Это не
перенос прошлогодних событий на текущий год. Несколько неоднозначных дат
пропускаются. Афиши, у которых дата или время указаны **только внутри
картинки**, пока пропускаются: OCR и догадки не используются.

Есть ссылка на исходную публикацию. События не помечаются как проверенные
человеком. Отмена отдельным новым постом, не содержащим данных об исходном
событии, требует ручной проверки организатором; код не обещает распознавать
такую связь. Опубликованные на сайте даты автоматически скрываются после
последнего дня в местном часовом поясе. Старые файлы фотографий не удаляются.
Дубли между ручной афишей и импортом исключаются по городу, дате и названию.

## Российские праздники

Используется официальный экспорт Calend.ru «Праздники России»:
`https://www.calend.ru/ical/ical-russtate.ics?v=yy2026&b=1`
(год подставляется при сборе). Принимаются только события категории
«Праздники России» с абсолютной датой текущего года. RRULE не переносится
на другие годы: переходящие даты должны поступить из нового экспорта.

На сайт передаются только названия, даты и ссылки. Тексты описаний и
иллюстрации Calend.ru не копируются. Во вкладке «Сегодня» показываются до
трёх праздников текущего местного дня со ссылками на источник. Категория
включает и официальные, и неофициальные российские даты; это не перечень
нерабочих дней. Иностранные календари не загружаются.

## Публикация и проверка

Workflow `City afisha and Russian holidays` запускается после изменения
сборщика в mewars, вручную и каждые три часа. В PR запускаются только
изолированные тесты; публикация лент выполняется только из mewars.

Результаты: `/feeds/calendar-ru.json`, `/feeds/afisha-vk.json`, фотографии
`/events/imported/`. Схема и данные Supabase не меняются. Перед загрузкой
проверяется реальный путь public_html и сохраняется приватная копия прежних
JSON. При ошибке источника прежняя лента сохраняется. Клиент скрывает
устаревшую афишу через три дня без обновления, календарь — через восемь дней.
Отчёт доступен как artifact `city-feed-collection-report` и содержит только
статусы/счётчики, без секретов и личных данных жителей.

Проверки: `python tests/city-feeds.py`, `node --loader
./tests/typescript-loader.mjs --test tests/city-feeds.test.mjs`, штатные
браузерные проверки главной и стены. Сборщик новостей администрации остаётся
отключённым.
