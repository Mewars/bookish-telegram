# Комментарии и обычные заявки в друзья

Подготовленные изменения, не подтверждение публикации на сайте.

## Стена

Форма нового комментария видна под каждой опубликованной записью без дополнительного раскрытия; вошедшие жители могут писать через существующий серверный RPC с прежним режимом модерации и антиспамом. Под собственным комментарием — «Удалить свой комментарий», под чужим у городского модератора остаётся «Скрыть». Серверный `delete_community_comment` физически удаляет строку и текст. Житель удаляет только своё, действующий owner/editor — в своём городе, глобальный owner — во всей сети. Для лимита спама отдельно сохраняются только ID, автор и исходное время недавних удалённых комментариев в закрытой таблице `community_comment_rate_log`, без текста. Новый RPC создания учитывает живые и удалённые комментарии вместе. Старые записи журнала пользователя очищаются при его следующем комментарии. Нельзя удалить чужой комментарий подменой идентификатора. Ответы сохраняются после удаления родителя, их FK становится NULL.

Добавлено «Ответить»: над полем появляется адресат и краткий фрагмент, ответ можно отменить. Серверный `reply_community_comment` разрешает ответ только на опубликованный комментарий той же записи, сохраняет действующую модерацию и антиспам. Поле остаётся доступно после отправки.

Владелец разрешил включение; перед публикацией применить `docs/sql/resident-comment-removal-v1.sql`. SQL применяется отдельно после проверки и до публикации интерфейса. Не удаляет существующие комментарии при установке.

## Друзья

Расширяется существующая SQLite-система `NearbyStore`, отдельный конкурирующий граф друзей не создаётся. Добавляется `social_directory` (идентификатор + выбранный пользователем город), по умолчанию пустая. Старые пользователи не включаются в поиск автоматически. Пользователь отдельно разрешает поиск своего имени в выбранном городе и может выключить его. Поиск доступен вошедшим, возвращает до 25 записей текущего города с именем и состоянием отношений; никаких телефонов, email, кодов приглашений, геолокации или списков чужих друзей. Блокировки работают в обе стороны. Город — выбранная пользователем публичная принадлежность, не подтверждение места проживания.

Прямые заявки используют существующую таблицу friendships и общую квоту приглашений; только получатель принимает заявку, встречная заявка не подтверждает её автоматически. Коды приглашений и существующие друзья сохраняются. Отключение поиска сохраняет друзей, полное удаление данных раздела удаляет и поиск. Геолокация не включается при вступлении в поиск или добавлении друга; ранее вручную включённая точка по прежним правилам доступна всем подтверждённым друзьям до конца часа, включая новых — это уже явно объясняется в интерфейсе.

Новые методы: `nearby_directory_opt_in`, `nearby_directory`, `nearby_request_person`. Интерфейс показывается только при `directory_enabled=true` от обновлённого сервера. На стене ссылки «Добавить в друзья» ведут к поиску конкретного автора; если автор не включил поиск, это объясняется без обхода приватности.

Развёртывание требует отдельного согласования обновления приватного модуля Sprinthost: конструктор создаст только новую SQLite-таблицу и индекс. Перед ним нужно проверить фактический путь, сделать согласованную онлайн-копию SQLite и сравнить рабочие серверные файлы с исходниками; существующий install-friends-host.sh автоматически не запускать, он переписывает config.json. Не меняем конфигурацию, секреты, DNS, геолокационные согласия. Ранее наблюдавшийся HTTP503 при проверке поддельного токена Friends остаётся отдельным неустранённым ограничением; нельзя заявлять, что hosted Auth проверен этим PR.

## Истории

Рабочий `list_city_stories` и RLS уже разрешают всем жителям/гостям смотреть опубликованные и ещё действующие истории выбранного города. Проверки дружбы в них нет. Не изменять их на friends-only. Записи и истории проходят модерацию; комментарии подчиняются существующим настройкам города. Видео/музыка в отдельном PR190 всё ещё ждут разрешения на SQL v2.

## Проверки

`node --test tests/resident-comments.test.mjs`: автор, чужой пользователь, гость, запрет прямых обновлений, повторное удаление, очистка текста, сохранение квоты.
`php tests/friends-host.php`: прежний набор безопасности + поиск по городам/добровольность/буквальные wildcard-символы/блокировки/прямые заявки/подтверждение/выключение поиска/удаление профиля. PHP запускается в CI; локального PHP в текущей среде нет.

Включение обновления сервера теперь подготовлено в `scripts/update-friends-social.sh` и `scripts/upgrade-friends-social.php`: точный путь, сверка исходных SHA с проверенной версией (отказ при ручных изменениях), приватная онлайн-копия `VACUUM INTO`, `quick_check` копии до изменения, сохранение старых модулей, узкая замена двух PHP-файлов, проверка новой таблицы и Auth. Настройки и cron не меняются; старый installer не используется. После согласования владельцем шаг включён в production workflow, после публикации статической части. При ошибке Auth новая статическая версия уже может быть опубликована — сообщать раздельно.
