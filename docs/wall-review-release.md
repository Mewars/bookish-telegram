# Стена: причины отказа и повторная отправка

## Поведение

Житель пишет запись или вопрос, сохраняет вложения и отправляет на проверку.
До решения модератора запись не видна в публичной ленте.
Отказ требует причины длиной 3–1000 символов. Причину видит автор в «Моих записях»; автор исправляет запись, сохраняет её как черновик и отправляет повторно.
Городской редактор принимает решения только в своём городе и не проверяет собственные записи. Глобальный владелец работает во всех городах и может одобрить собственную запись.

Комментарии сохраняют существующую отдельную настройку. Изменение касается записей и вопросов жителей.

## Изменения

- В host-public/wall сохранены действующие HTML и JS модуля /wall/, прочитанные с сайта 20.10.2026. SDK, CSS, медиа и другие модули хостинга не заменяются.
- Реальные фото, видео, реакции, автосохранение и функции владельца сохранены.
- Сохранение отклонённой записи проверяет автора, допустимый статус и факт обновления, затем возвращает запись в draft до загрузки новых вложений.
- «Мои записи» учитывает выбранный город.
- Причины отказа находятся в отдельной таблице с RLS. Публичной роли доступ запрещён. Жители не могут записывать причины самостоятельно.
- Стандартный React-интерфейс закрытой беты также получает причины отказа; публичный маршрут не переключается на бету.

## Порядок выпуска

1. Успешные проверки PR, включая изолированный PostgreSQL и браузерные сценарии.
2. Применить docs/sql/community-review-reasons-v1.sql сначала к Test, проверить RLS и RPC, затем к Production в рамках согласованного выпуска.
3. Объединить PR и выпустить код. Проверка перед публикацией останавливает деплой, если приватная таблица отсутствует или доступна анонимно.
4. На хостинге предварительно архивируются classifieds и wall, корневые HTML и служебные файлы. SDK стены проверяется на наличие и не перезаписывается.
5. После выпуска проверить роль жителя и владельца. Изолированные тесты не подтверждают доставку уведомлений и работоспособность OAuth на реальных устройствах.

SQL не меняет существующие записи жителей. Старый двухаргументный review_community_post сохраняет одобрение, а отклонение без причины запрещает.
При откате клиента новый сервер намеренно продолжит запрещать отказ без причины; для управления отказами нужно сохранить новый клиент.

## Автотесты

- RLS: автор, другой житель, редакторы разных городов, владелец и аноним.
- Невозможность самостоятельной публикации и изменения причин.
- Причина не попадает в публичную ленту, а после одобрения удаляется.
- Исправление, повторная отправка и подключение будущего города.
- Браузер 390/1440: отказ с причиной → исправление жителем → повторная модерация → одобрение владельцем; фильтрация городов.
- Нулевой результат UPDATE не выдаётся за успешное сохранение.
