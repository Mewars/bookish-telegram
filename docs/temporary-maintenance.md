# Временное закрытие РЯДОМ

29.10.2026. Включено по просьбе владельца на время подготовки переноса.

- Переключатель: `public/maintenance/config.json`, строго `{"enabled":true}`.
- Production: после обычной сборки и сохранения host-расширений скрипт
  `scripts/prepare-maintenance.py` заменяет HTML-входы статической страницей.
  Исходники приложения и данные не удаляются. Теги расширений главной остаются
  внутри инертного `<template>` для восстановления следующей обычной сборкой.
- На Sprinthost перед изменением `.htaccess` создаётся штатная приватная копия.
  Скрипт добавляет отдельный маркированный блок, сохраняя остальные правила.
  Прямые host-маршруты, включая API, получают 503. Картинки плашки, конфигурация,
  версия и ACME доступны для проверки и продления сертификата.
- Страница не запускает приложение, авторизацию, аналитику или запросы к БД.
  Это закрытие веб-сайта, а не отключение Supabase: существующие токены и прямые
  обращения к внешнему backend этим изменением не отзываются. Уже собранные
  данные и обязанности по ним сохраняются.
- GitHub Pages и ручной ZIP также получают статический экран; Pages не
  поддерживает `.htaccess` и возвращает собственный HTTP-статус для HTML.
- Никакого публичного параметра обхода или исключения для администратора нет.
- Повторное открытие: только после проверки переноса и команды владельца
  установить `enabled:false`, выполнить проверенную сборку/публикацию. Она
  восстановит HTML приложения и удалит только маркированный блок `.htaccess`.
  Не удалять прежние host-правила и не подменять `.htaccess` целиком шаблоном.

Проверки: `python3 tests/maintenance.test.py`; CI требует реальный Apache.
Проверка опубликованной главной распознаёт режим и проверяет 503, картинки,
мобильную ширину и закрытые прямые ссылки. Она не выдаёт плашку за аудит БД.
