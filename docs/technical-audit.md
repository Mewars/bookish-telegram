# Технический аудит «Рядом»

Дата: 11 октября 2026 года. Репозиторий: `Mewars/bookish-telegram`.
База: актуальный `mewars`, коммит `c05cb43` (включает PR #25 и #26).
Рабочая ветка: `codex/technical-audit`. Проверен открытый PR #24: только инструкция миграции на Timeweb, пересечения с этим аудитом нет.

## Область и ограничения

Проверены исходный код, production-сборка с base `/` и пользовательские сценарии в локальном Chromium через Playwright. Проверки адаптации выполнены на 320, 375, 390, 430, 768 и 1440 px, в светлой и тёмной темах. Проверены обычный браузер и тестовый Telegram-контекст.

`https://ryadomcity.ru` недоступен из среды аудита: сетевой proxy возвращает HTTP 403 на CONNECT. Это ограничение среды, а не доказательство неисправности сайта. Состояние опубликованной версии, SSL, HTTP-заголовки и доступность из РФ не подтверждены этим аудитом. Реальный iPhone 13, Safari и Chrome на iOS не использовались; WebKit runtime отсутствует. Проверка ширины 390 px в Chromium не заменяет проверку на устройстве.

Supabase в локальной сборке не настроен — проверен гостевой fallback. Email/OAuth/восстановление/выход проверены только с подменённым локальным клиентом; реальные запросы входа, отправка писем и операции с production-данными не выполнялись. Карта с координатами проверена на браузерной фикстуре: координаты каталога не менялись. Живые тайлы OSM и реальный радиопоток не подтверждены: проверены контракт карты, воспроизведение с тестовыми media events и отказ внешнего ресурса.

Production, Supabase/RLS/Auth configuration, DNS, SSL, Спринтхост, GitHub Pages, Netlify workflows, платежи, каталог и утверждённые hero/изображения не изменены.

## Проверенные сценарии

### Страницы, навигация, поиск и хранение

- Главная, места, афиша, услуги, избранное, профиль, login, privacy, cookies, terms, contacts, consent, карточка организации и importer: **168 сочетаний экран × ширина × тема** на dev-сервере и ещё **168 на production preview**, без document horizontal overflow и необработанных JS-ошибок.
- Быстрые категории, поиск по кириллице, категории каталога и «Сегодня»/«Завтра», очистка поиска и сброс пустой выдачи работают. Несуществующая карточка показывает fallback с возвратом на главную.
- Добавление/удаление гостевого избранного, сохранение после reload, счётчик и пустое избранное работают. Theme settings сохраняются; city picker открывается, закрывается Escape и возвращает фокус.
- При запрете localStorage приложение рендерится; избранное доступно в памяти с предупреждением, тема переключается, ошибка сохранения города показана, регистрационное согласие не считается сохранённым.
- Music play/pause, mute, volume, раскрытие/закрытие панели проверены с тестовыми media events. Cookie-панель, раскрытый плеер и нижняя навигация не пересекаются на заданных ширинах при bottom safe-area 20 px. Автоматического запуска радио нет. В коде есть обработка отказа `play()`, media error и таймаут 15 секунд.
- Проверены Tab-focus и reduced-motion. Отдельно проверены **52 production-перехода с декодированием изображений**, загрузка локального hero JPEG и favicon SVG (HTTP 200), JS/CSS без HTTP ошибок. Скриншоты 390/1440 px в обеих темах просмотрены локально.
- Importer принимает тестовый CSV и скачивает JSON локально; в этом сценарии сетевых запросов не было.

### OpenStreetMap

- Проверены все 10 реальных карточек на 390/1440 px, основные разделы и координатная фикстура: **36 сценариев**, без route buttons или `rtext` в DOM.
- В текущих реальных данных нет координат: встроенная карта не создаётся по адресу; для city + address есть корректно encoded HTTPS-поиск Яндекса. У памятника без адреса карта не выдумывается. Данные не дополнялись геокодингом.
- С координатами карта не запрашивается до клика; iframe использует supplied marker/bbox. Opening links OSM/Яндекс и attribution © OpenStreetMap сохранены, внешние ссылки имеют `target="_blank"`, `rel="noopener noreferrer"`.
- Невалидные координаты, граничные широты, отсутствие адреса/города и приоритет supplied Yandex URL покрыты существующими тестами. Платных API/ключей Яндекс Maps нет.
- Helpers ещё могут возвращать route URLs для совместимости тестов; UI их не отображает.

### Auth, данные и согласия

- Email signin, signup, password mismatch, required registration consent, reset email, invalid recovery link, new password, OAuth consent/callback/error, signout проверены на локальном mock-клиенте. Для email callback сохраняется `#/login`, для recovery — `ryadom_recovery=1`; OAuth использует origin + Vite base. При reject появляется ошибка и повторное действие доступно.
- `AuthProvider` обрабатывает reject/getSession error; async профиль защищён revision checks от устаревших сессий. Favorites имеют отдельный user cache, проверку session owner и последовательную очередь мутаций. Реальная синхронизация разных устройств/аккаунтов не проверена без тестовой базы и входа.
- В `supabase/schema.sql` есть RLS и own-user policies для profiles/identities/favorites. Наличие этих правил в действующей БД не подтверждено и не менялось. Миграции не запускались.
- Public config принимает HTTPS и `sb_publishable_`, не server key. `authStorage` удаляет provider access/refresh tokens из сохраняемой сессии. Сессия Supabase хранится в браузере, поэтому CSP/XSS-hardening стоит рассматривать отдельным согласованным этапом, а не утверждать полную защиту по одному code review.
- Cookie consent проверен отдельно от PD consent. Metrika включается только в production origin после согласия; код очищает OAuth/Telegram private URL parameters перед hit. Проверка живого production counter и HTTP security headers недоступна.
- **12 production-browser Telegram сценариев** на 390/1440: обычный браузер делает 0 SDK-запросов; error/5-second timeout не блокируют страницы и поиск; поздний SDK, cached launch и injected Mini App работают.

- `npm run build` успешно создаёт `dist/index.html`, `assets/`, `brand/yeniseysk-hero-final.jpg`, `brand/pin-yellow.svg`. JS/CSS root URLs `/assets/...`; нет `/bookish-telegram/` в index HTML. Hash-навигация работает на статической production-сборке.
- Локально создан и проверен ZIP с 10 build-файлами: `index.html`/`assets` в корне, без дополнительного `dist/`, исходников, `.env`, `.git`, `node_modules`, source maps; CRC проверен. ZIP использовался только для проверки и не загружался на хостинг.
- В публичной локальной сборке не найдены private-key/`sb_secret_` patterns или JWT с role `service_role`. Это проверка артефакта, не доказательство отсутствия всех возможных секретов. Production Secrets не читались; локальная сборка без них не подтверждает их текущую настройку.
- Существующий `.github/workflows/sprinthost-build.yml`: только `workflow_dispatch`, Node 24, `npm ci`, lint/maps/OSM/import, проверка публичной конфигурации, base `/`, ZIP contents без wrapper folder, upload artifact. Workflow сохранён без изменений; реальный GitHub Actions запуск с Secrets в рамках аудита не выполнялся.
- `npm audit --omit=dev` и полный `npm audit`: **0 известных vulnerabilities** на дату проверки (включая dev dependencies во втором запуске). Это проверка известных advisories, а не гарантия отсутствия уязвимостей.
