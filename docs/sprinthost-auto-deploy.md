# Автоматическая публикация «Рядом» на Спринтхосте

**Сайт:** https://ryadomcity.ru  
**GitHub:** Mewars/bookish-telegram, ветка `mewars`  
**Каталог на Спринтхосте:** `/home/mewars/domains/ryadomcity.ru/public_html/` (не `mewars.xsph.ru`).

## Пока не включено

`.github/workflows/sprinthost-deploy.yml` намеренно **ничего не отправляет** на сервер, пока владелец не создаст защищённый SSH-доступ и не задаст переменную `SPRINTHOST_DEPLOY_ENABLED=true` в GitHub Actions.

Workflow исполняется только для ветки `mewars` (после merge) или вручную; проверяет код, выполняет сборку, проверяет версию и путь, загружает сначала ресурсы, потом `index.html` и `version.json`. Он не использует `--delete`, чтобы сохранить старые версии ресурсов во время обновления и пользовательские файлы на хостинге. Пароли не хранятся в репозитории.

## Настройка владельцем (один раз)

1. Убедиться в панели Спринтхоста, что SSH включён, записать подтверждённый серверный IP и порт. Документация: https://help.sprinthost.ru/file-transfer/ssh-and-sftp .
2. Создать **отдельную** пару SSH-ключей специально для GitHub Actions. Открытый ключ добавить к аккаунту хостинга в `~/.ssh/authorized_keys`. Закрытый ключ хранить только в локально защищённом месте и GitHub Secrets; никому не присылать. Проверить, что подключение с ключом действительно работает. Предпочитать отдельного пользователя с правами только на каталог сайта, если хостинг поддерживает такую конфигурацию.
3. Проверить подлинность ключа хоста SSH (fingerprint) через надёжный канал и сформировать `known_hosts` **после** проверки отпечатка.
4. В GitHub → Settings → Secrets and variables → Actions → **Repository secrets** создать:
   - `SPRINTHOST_SSH_HOST`: подтверждённый IP/домен сервера Спринтхоста;
   - `SPRINTHOST_SSH_USER`: логин пользователя SSH (в текущем аккаунте `mewars`, если не создан отдельный);
   - `SPRINTHOST_SSH_PRIVATE_KEY`: весь закрытый SSH-ключ, включая строки BEGIN/END;
   - `SPRINTHOST_SSH_KNOWN_HOSTS`: подтверждённая запись `known_hosts` для сервера.
   Существующие `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` оставлять как есть.
5. При нестандартном порте добавить GitHub → Actions → Variables: `SPRINTHOST_SSH_PORT`. По умолчанию 22.
6. После отдельной проверки соединения создать **Repository variable** `SPRINTHOST_DEPLOY_ENABLED` со значением `true`, затем вручную запустить **Deploy Ryadom to Sprinthost** на ветке `mewars`. Убедиться, что проверки зелёные и на сайте появился новый `version.json`.
7. Далее при каждом одобренном merge в `mewars` сайт будет обновляться автоматически. Если нужно приостановить публикации, изменить `SPRINTHOST_DEPLOY_ENABLED` на `false`.

## Кеш и обновления

Vite записывает одинаковый ID сборки в метатег `index.html` и `/version.json`. `.htaccess` запрещает кеширование этих двух файлов, а JS/CSS с хешем могут кешироваться долго. Открытый сайт проверяет версию при возвращении во вкладку и каждые 5 минут. При изменении предлагает пользователю обновиться кнопкой, но не перезагружает форму автоматически.

## Безопасность и откат

- **Не используйте** ключи Supabase service_role, Secret key, GitHub PAT или пароль от Спринтхоста вместо SSH-ключа.
- Никогда не размещайте закрытый ключ, пароль и `authorized_keys` в `public_html` или GitHub исходниках.
- Не включайте прямую публикацию для feature-веток и PR.
- Если новый релиз проблемный, отключите переменную `SPRINTHOST_DEPLOY_ENABLED`; вручную восстановите прошлый архив `sprinthost-site.zip` из ранее успешно собранного выпуска или подготовьте PR с откатом.
- Проверьте, что Спринтхост действительно применяет `.htaccess`: ответ `curl -I https://ryadomcity.ru/version.json` должен содержать `Cache-Control: no-store`.
